# Core runtime dependencies for Paprika Lyrics
#
# Pinned exactly, not floored. The release workflow installs from this file and
# packages whatever it resolves, so a floating range means the shipped build
# changes under the user without a commit: a future pywebview major (which owns
# the WebView2 host and its native loader) or winsdk (which owns the GSMTC
# transport) could land in a tagged release that was never tested against it.
# These are the versions the app was verified on (Windows, Python 3.10-3.13);
# bump them deliberately, in a commit, with a test run.
pywebview==6.2.1
winsdk==1.0.0b10
requests==2.32.3
# Optional: spotifyscraper >= 3.9.2, which is what `spotify_scraper` on PyPI
#   is called (the project is AliAkhtari78/SpotifyScraper).
#   A second Spotify track-ID lookup, imported behind a guard
#   (core.resolver.SPOTIFY_SCRAPER_AVAILABLE) and tried FIRST when present.
#   Deliberately not pinned: nothing needs it, because core/resolver.py resolves
#   track IDs itself over `requests` alone — the tier a packaged exe runs — and
#   pinning it would put an HTML scraper and httpx inside every shipped build for
#   a fallback that is already covered. Install it for a source checkout with
#   `pip install spotifyscraper==3.9.2` and it takes its usual place in front.
# spotifyscraper==3.9.2
